# Implemented-feature record

## Phase 1: IMPLEMENTED (code exists and is tested)
- [x] Modular project layout, CLI (`generate|validate|features|db|all|adapt-sms`)
- [x] Raw schemas: users, conversations, messages, transactions (+ data_source on every row)
- [x] Seeded synthetic generator: 4 scam + 5 benign scenarios, lifecycle stages, noisy UPI IDs, unpaid scams, txn-only fraud, reused payees
- [x] Ground truth kept separate (evaluation only)
- [x] Message features: payment request, UPI/amount extraction, urgency, keywords, suspicious links, TF-IDF-ready text
- [x] Conversation features: frequency/timing statistics and payment-request timing
- [x] Transaction features: amount, time, history deviation, velocity, beneficiary behaviour (no look-ahead)
- [x] Validation: schema, missing, timestamps, amounts, duplicates, identifier consistency (negative tests)
- [x] SQLite export, README, 29 pytest tests
- [x] Public SMS adapter (format-tested on a fixture only; not run on the real public file)



## Phase 2: IMPLEMENTED (code exists, tested, results generated by running it)
- [x] Messaging model: TF-IDF + content indicators + Logistic Regression; 4 variants for ablation
- [x] New indicators: credential-request detection (warning-aware), repeated persuasion, one-sided pressure
- [x] Payment models: Logistic Regression baseline + Random Forest, class weights, rule baseline for context
- [x] Evaluation: temporal + random split (payment); random + leave-one-scam-scenario-out (messaging); P/R/F1/ROC-AUC/PR-AUC, confusion matrices, bootstrap CIs, per-scenario errors
- [x] Out-of-template probe set (13 hand-written conversations) showing the messaging model does not generalise beyond templates
- [x] Shared output contract + validator; invalid-input errors for both models
- [x] Inference path for new conversations/transactions, tested for parity with the training features
- [x] Out-of-fold score tables for Phase 3 (`scores_messaging_oof.csv`, `scores_payment_oof.csv`)
- [x] 86 tests total

## Known gaps in Phase 2
- [ ] Credential-request indicator cannot be learned (no such messages in the data); rule signal only
- [ ] Messaging model fails on out-of-template scams (0/6 in the probe)
- [ ] No probability calibration; scores from the two models are on different scales

## Not implemented (proposed): Phase 3 cross-platform correlation (entity resolution, temporal matching, graph, combined score, early-warning evaluation), Phase 4+ API/dashboard
